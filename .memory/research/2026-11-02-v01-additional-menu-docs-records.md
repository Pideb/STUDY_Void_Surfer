# 추가 요청: 메뉴·기체 임시 해금·문서·비공개 플레이 기록

- Date: 2026-11-02
- Status: confirmed. 추가 인터뷰 종료, 모든 요구와 A01~A13 확정. [최종 결정](../decisions/2026-11-02-v02-feedback-release.md)과 [v0.2 실행 계획](../plans/2026-11-02-v02-feedback-release.md)이 최종 기준이다. 본 게임 구현·배포는 아직.
- 기준 계획: [v0.1 통합 계획](../plans/2026-11-02-v01-gameplay-visual-polish.md). 기존 확정 게임 디자인/수치를 취소하지 않는다.
- 질문은 일반 응답 본문에 하나씩, 추천과 2~3개 선택지. 승인된 항목을 반복 질문하지 않는다.

## 사용자 추가 요구

1. v0.3 전까지 로그인·게스트 포함 모든 사용자 모든 기체 임시 해금. 표시 문구는 '다음 버전까지 임시 해금' 요청. 영구 최고기록/실제 계정 해금 점수를 조작하지 않는 임시 정책으로 구성할 것.
2. 게임오버 재시작 버튼 제거. 중앙 팝업 밖 클릭/터치 또는 ESC 외 모든 키로 즉시 재시작, ESC는 메인 메뉴. 팝업 내부 메뉴/랭킹 클릭은 기존 기능 유지. 게임오버에서는 방향키/Space도 재시작이며 파일럿 랭킹은 키보드 선택에서 제외한다(A02).
3. 메인·기체 선택 등 모든 메뉴 방향키 탐색, 기존 hover와 같은 선택 표시, Space 활성화. 문서/입력창/팝업과 플레이 키 핸들러 충돌, held-key/repeat/게임오버 전환 직전 입력 재사용 방지 필요.
4. HTML의 과거 두 버전 표시를 v0.1 / v0.1b로 변경. 사용자2번 선택으로 이번 작업의 다음 배포는 v0.2로 확정했다. 과거 내부 식별자/검증 증거/해시/보호된 스냅샷을 새 배포처럼 다시 쓰지 않는다. 실제 registry와 생성 파이프라인 변경은 후속 실행에서 처리한다.
5. 관리 레퍼런스 HTML에 개발 예시 HTML 링크 모음 탭 추가. 실제 독립 미리보기만 대상으로 content.html 조각/fixture/측정용 내부 페이지와 구분. 상대 링크의 실행 환경/외부 공유 가능 범위는 설계 필요.
6. 플레이어용 HTML 새로 제작. 기본 조작키와 개발자 수동 작성 업데이트 내역 포함. 게임 소스에서 임의로 유저용 업데이트 문구 생성하지 않는다.
7. 시작~사망 플레이시간과 총 플레이 횟수 기록, 사용자에게 노출하지 않음. 사용자1번 선택으로 로그인·게스트 모두 Supabase에 기록하고 개발자만 조회(A03). 시간 집계/중도 이탈 집계 여부는 후속 확인. 브라우저에 숨기기만 하는 것은 서버 조회 권한 차단과 다르다.
8. 게임오버 팝업 바깥을 살짝 어둡게 하고 화면 하단에 '아무 키 입력/화면 클릭을 통해 재시작' 문구를 잘 보이는 네온 스타일로 추가(A04).
9. 보스 속도 패턴은 첫 번째 저속, 두 번째 고속, 세 번째 변속, 네 번째부터 모두 무작위로 변경(A08). 지역/외형 순서 변경과 구분한다.
10. 모바일은 가로 모드 필수. 세로 모드에서 기존 게임의 우주+네온 디자인에 맞는 회전 안내창을 띄운다(A10).
11. PC 해상도에 따라 메뉴 크기가 제각각이지 않게 자동 조절한다. 사용자1번 선택: 기준 시안 전체를 일괄 확대/축소하여 화면 대비 같은 비율을 유지(A11).

## 코드 조사

- aircraft.js::canSelectAircraft는 게스트 default만, 계정은 기존 최고점수 기준. UI만 해금해서는 엔진 검증에서 다시 거절될 수 있으므로 공통 정책을 갱신해야 한다.
- screens.js::renderGameOverScreen은 재시작/랭킹/메인 버튼과 점수 저장 메시지·리더보드가 있다.
- app-controller.js에 전역 keydown과 게임오버 데이터 저장 경로가 있다. 새 핸들러를 무조건 중복 추가하지 않는다.
- 기존 elapsedSeconds는 일부 QTE/정지 등에서 흐르지 않으므로 사용자 의미의 시작~죽음 경과시간과 자동으로 같지 않다.
- releases.json의 실제 운영0.01-b·과거0.01v·보호snapshot해시와 nextVersion0.1을 확인했다. 표시 이름과 배포 식별자를 구분해 보존해야 한다.
- .memory/validation 아래 독립 preview/review/playtest와 내부 content/fixture/runtime가 혼재한다. 링크 수집은 파일을 무차별 노출하지 않고 검토용 목록으로 만들 것.

## A01 확정: 과거 표시 이름과 다음 배포 버전

- 사용자 선택2: 과거 HTML 표기는 v0.1 / v0.1b, 이번 작업의 다음 실제 배포는 v0.2.
- 이는 기존 '다음0.1' 계획을 명시적으로 대체한다. 과거 배포 기록과 원본 보호 스냅샷은 보존하며 표시 이름과 내부 식별자를 구분한다.
- 현재 운영 배포는 내부0.01-b 그대로다. 이 답변만으로 배포/prepare/push를 실행하지 않는다.
- v0.2 이후의 세부 증가 방식은 아직 이번 선택으로 정하지 않았다. 기체 임시 해금은 사용자 요청대로 v0.3 전까지이며 실제 해금 점수는 조작하지 않는다.

## A02 확정: 게임오버 키 입력 예외

- 사용자 명시: 모든 키는 재시작, ESC만 메인 메뉴로 이동. 파일럿 랭킹은 마우스로만 선택한다.
- 게임오버는 일반 메뉴 방향키/Space 탐색 규칙의 예외다. 방향키/Space/Enter도 재시작이며 랭킹 버튼을 키보드 선택 대상으로 활성화하지 않는다. 다른 메뉴의 키보드 탐색 요구는 유지한다.
- 기존 '재시작' 버튼 제거 및 팝업 바깥 클릭/터치 재시작은 유지한다. 팝업 안의 일반 영역을 눌렀다고 재시작하지 않으며 기존 메뉴/랭킹 포인터 동작은 보존한다.
- 구현상 held-key/repeat/사망 전 입력의 재사용을 차단하고 게임오버가 열린 뒤의 새 입력만 처리한다. ESC가 메뉴 이동과 재시작을 동시에 실행하지 않게 입력당 화면전환 한 번만 처리한다.
- 브라우저/OS가 가로채 앱에 전달되지 않는 단축키까지 보장한다는 뜻은 아니다. 앱에 들어오는 키 입력에 적용한다.
- 코드 조사상 점수 저장은 게임오버 비동기 경로에 있으므로 즉시 재시작/ESC 후에도 해당 run의 점수·플레이기록 전송이 새 run 상태를 덮어쓰거나 누락되지 않게 별도 수명·중복방지 검증이 필요하다.

## A03 확정: 로그인·게스트 모두 서버에 비공개 플레이 기록

- 사용자1번 선택: Supabase에 로그인·게스트 모두 기록. 로그인 계정 식별자 또는 게스트 익명 식별자로 구분하며 개발자만 조회한다.
- 새 기록 조회를 공개 리더보드 RPC나 사용자용 화면에 포함하지 않는다. 기존 리더보드의 읽기 정책을 재사용해 전체 이용자에게 플레이 로그를 노출하지 않는다. 서버의 실제 읽기 권한으로 제한한다.
- 브라우저에 관리자 비밀키를 넣지 않는다. 쓰기 전용 경로와 서버 중복방지/run 식별을 청사진에서 정의한다. 비공개 저장은 사용자에게 총 횟수/시간 조회 UI를 제공하지 않는다는 뜻이며 게스트 최고점수 저장 정책을 변경하는 요청은 아니다.
- 현재는 요구 확정이며 SQL migration/클라이언트 구현/원격 DB 적용은 아직 하지 않았다. 플레이시간은 A05, 총횟수는 A06을 따른다.

## A04 확정: 게임오버 배경과 재시작 하단 안내

- 사용자 요청 그대로 팝업 바깥의 게임 화면만 살짝 어둡게 한다. 중앙 결과 팝업과 하단 안내의 가독성은 유지한다.
- 화면 하단의 정확한 문구: '아무 키 입력/화면 클릭을 통해 재시작'. 밝고 선명한 글자와 게임에 맞는 네온 광으로 표현한다. 과도한 번짐 때문에 글자가 흐려지거나 모바일 safe-area 밖으로 잘리지 않게 한다.
- 새 문구가 A02 입력 규칙을 바꾸지 않는다. ESC는 메인 메뉴, 다른 새 키 입력과 팝업 바깥 클릭/터치는 재시작, 팝업 내부 메뉴·랭킹 포인터 동작은 그대로다.
- 오버레이 색/알파/글꼴 크기는 기존 화면과 모바일을 고려한 구현 기본값이며 별도로 사용자 확정 수치라고 적지 않는다. 새 고비용 전체화면 필터/깜빡임은 이 요청에 포함하지 않는다.

## A05 확정: 플레이시간 기준

- 사용자1번 선택: 실제 플레이가 시작된 순간부터 사망 판정 순간까지 측정한다. 출격 준비와 일시정지는 제외하고 WASD 챌린지 시간은 포함한다.
- 출격하기 버튼을 누른 시각이나 음악 준비 시작을 플레이 시작으로 쓰지 않는다. 사망 뒤 폭발 연출/게임오버 팝업 체류 시간도 포함하지 않는다.
- 기존 game-engine.elapsedSeconds는 WASD 중 증가하지 않아 그대로 재사용하면 승인 기준과 달라진다. 별도의 run 시간 측정을 사용하고 pause/resume으로 제외 시간을 처리한다. 물리 프레임 dt 상한으로 렉 구간의 기록 시간이 짧아지지 않게 설계한다.
- 즉시 재시작/ESC/저장 재시도가 사망한 run의 측정값을 바꾸지 않게 사망 순간 결과를 고정하고 run별 중복 기록을 방지한다.
- 총횟수는 후속 A06을 따른다. 시작~사망 시간 규칙과 중도 이탈 기록의 완결 여부를 구분한다.

## A06 확정: 시작 기준 총 플레이 횟수

- 사용자1번 선택: 실제 플레이가 시작되면1회로 세며 도중에 나간 판도 포함한다. 사망까지 완료한 판은 별도 상태로 구분한다.
- 출격 준비/음악 대기/준비 중 취소는 총횟수에 포함하지 않는다. 즉시 재시작도 새 실제 플레이가 시작될 때 새 run으로1회 집계한다.
- run 식별자를 키로 시작 기록/완료 기록을 연결한다. 통신 재시도/결과창 재진입/중복 이벤트로 횟수가 증가하지 않게 한다. 단순 클라이언트 누적값 덮어쓰기 대신 서버의 중복 없는 run 집계로 설계한다.
- 사망한 판의 시간은 A05대로 고정한다. 브라우저 종료 등으로 완료 이벤트를 전송하지 못한 시작 기록은 사망 완료로 조작하지 않고 미완료 상태로 남겨 총 시작횟수에 포함한다. 이 경우 정확한 이탈 순간/사망시간이 확인됐다고 주장하지 않는다.
- 게스트 최고점수 저장이나 사용자에게 기록을 보여주는 기능은 추가하지 않는다. 기존 계정/게스트 리더보드 정책과 별도 개발자용 통계다.

## 링크 탭 조사 메모

- 개발 예시는 .memory/validation 아래에 있고 프로젝트 기본 빌드가 이 폴더를 자동 공개하는 구조는 아니다. 관리 HTML에 로컬 상대 링크만 추가해도 원격 배포 주소에서 그 자료가 열리는 것은 아니다.
- 사용자가 요청한 플레이어용 기본 조작/수동 업데이트 HTML과 개발 시안 보관 탭은 대상이 다르다. 공개 범위를 확인하기 전 .memory 전체를 public/dist로 복사하거나 내부 fixture/보고서를 무차별 노출하지 않는다.

## A07 확정: 개발 예시 링크 탭은 로컬 보관

- 사용자1번 선택: 개발자용 관리 HTML에 로컬 개발 자료로 보관하며 게임 배포에는 포함하지 않는다.
- 기존 독립 preview/review/playtest HTML의 제목·용도·날짜·원본 상대 경로·승인/폐기 상태를 목록으로 묶는다. content 조각·측정 fixture·내부 디버그 페이지를 무조건 예시 목록에 올리지 않는다.
- 링크 대상의 JS/이미지 의존성을 확인하고 로컬 파일/개발 서버 실행이 필요한 자료를 구분해 표시한다. 경로가 없는 예시를 열리는 링크처럼 기록하지 않는다.
- .memory/validation 전체를 public/dist로 복사하지 않는다. 기존 시안과 원본은 보존한다. 플레이어용 기본 조작/수동 업데이트 HTML과 혼합하지 않는다.

## A08 확정: 첫 세 보스의 속도 패턴 고정

- 사용자 명시: 첫 번째 저속 → 두 번째 고속 → 세 번째 변속 → 네 번째 이후 무작위.
- 현재 chooseBossPattern은 매번 세 속도 패턴에서 독립 균등 추첨한다. 네 번째부터 이 기존 무작위 방식을 유지한다. 셔플 백/연속 패턴 금지 같은 추가 제약은 요청되지 않았다.
- 순서는 한 플레이(run)의 보스 차수 기준이다. 새 게임/즉시 재시작은 첫 번째 저속부터 다시 시작한다. 지역 배경·보스 디자인 순서를 고정하는 뜻은 아니다.
- 기존 저속/고속 배율, 변속 주기, 2초 속도 보간, VELOCITY 고속 보정, 벽을 모두 보낸 후 보스 진입하는 규칙은 유지한다. 첫 세 보스라는 이유로 배율이나 속도 상한을 추가 변경하지 않는다.
- 난이도 조회가 매프레임 이뤄져도 보스 입장 전에 선택한 패턴이 전투 도중 재추첨되지 않게 한다. 첫 세 보스의 고정 패턴은 조회할 때마다 RNG를 소모하지 않게 하여 불필요한 난수 상태 변화를 막는다.
- 반영 대상 청사진에는 difficulty.js::chooseBossPattern/getDifficulty와 game-engine.js::startWarningIfNeeded의 bossEntry.pattern 선택 및 beginWarningSession의 고정 경로, 난이도·입장·재시작 회귀 테스트를 포함한다. 현재 실제 진입 함수와 필드를 확인했다.

## A09 확정: 가이드 왼쪽 / 음량 오른쪽

- 사용자1번 선택: 메인 메뉴에 '플레이 가이드' 진입 링크를 추가하고 별도 새 탭으로 플레이어용 HTML을 연다. 게임 메뉴는 유지한다.
- 사용자가 현재 메뉴 디자인을 마음에 들어 하므로 실제 적용될 모습의 시안을 먼저 보여주고 배치를 확정한다. 큰 메뉴 버튼으로 임의 추가하지 않는다.
- 시안: [플레이 가이드 메뉴](../validation/2026-11-02-v02-menu-guide/preview.html). 현재 실제 메뉴 함수·렌더·CSS·원본5PNG를 사용하고 음량 아이콘 옆에 작은 링크를 배치했다. 기본/선택 상태 캡처, 비교 탭, 3기체/계정 예시, PC/모바일 크기/전체화면, 방향키·Space 새 탭 열기 포함.
- 전체 skeleton 기반 단일 파일/Downloads 동일 사본, 로컬 오프라인 검증. 게임7소스/원본5자산SHA 불변,4크기 주요8영역 before/after 위치 동일,JS0,키보드 새 탭 열림 확인. 새 탭은 임시 안내 페이지이며 최종 사용자 문서를 만들었다는 뜻이 아니다.
- 낮은 가로 모바일의 기존 utility 행 잘림은 before/after 동일하다. 예정된 모바일 UI 작업에 메뉴 높이·스크롤 검증으로 연결하고 전체 모바일 사용성 통과라고 보고하지 않는다.
- 링크의 메인메뉴 진입/새탭 방식은 확정됐고 음량 옆 배치의 시각 승인은 아직이다. 다른 사용자 요구를 다시 질문하거나 시안 승인을 구현/배포 승인으로 확대하지 않는다.

## A10 추가 확정: 모바일 가로 화면 필수 / 세로 회전 안내

- 사용자 명시: 모바일은 반드시 가로 모드에서 이용하며 세로 모드일 때 가로로 돌려 달라는 안내창을 띄운다.
- 안내는 기존 실제 우주 배경과 네온 색상/글꼴/테두리 느낌을 사용한다. 모바일 세로 화면 전체에서 안내를 명확하게 읽을 수 있게 하고 게임/메뉴의 뒤쪽 입력이 통과하지 않게 설계한다.
- 안내창의 시각안은 이후 반응형 메뉴 시안과 함께 확인한다. 기기 자체의 회전을 강제로 보장하는 API가 아니라, 세로 화면에서 앱 사용을 막고 가로 복귀 시 안내를 해제하는 조건으로 구성한다.
- 코드에는 현재 전용 orientation gate가 없다. 기존 pause()는 -10점이고 QTE 중 호출을 무시하므로 회전 안내에 그대로 연결하면 감점/챌린지 진행 문제가 생긴다. 세로 전환 중 게임·챌린지·출격 준비 비동기 상태의 중지/복귀를 별도 검증 항목으로 설계할 필요가 있다. 구체 복귀 동작은 아직 승인된 결정으로 기재하지 않는다.
- PC의 세로로 긴 브라우저 창까지 무조건 모바일로 간주하지 않는다. 메뉴 UI 배율과 게임960×540 논리 월드/입력좌표/히트박스를 분리한다.

## A11 확정: PC 메뉴의 화면 대비 비율 통일

- 현재 CSS는 메뉴 padding/gap/wordmark에 vw/vh/clamp, 본문·버튼에는 rem을 혼용한다. 그래서 해상도 변화 시 요소마다 비율이 다르게 바뀔 수 있다.
- 사용자1번 선택: 화면 대비 같은 비율. 로고/기체/인사/버튼/계정을 한 묶음으로 확대·축소한다. 동일 CSS px 고정안은 채택하지 않는다.
- 승인된 v2 시안1600×900을 구현 기준으로 삼고 scale=min(width/1600,height/900), 울트라와이드는 여유를 두는 후보를 만들었다.1600×900은 사용자 별도 수치 선택이 아닌 승인 시안을 보존하기 위한 구현 기준이다.
- 정책은 PC 메뉴/팝업에 적용하는 방향으로 계획에 넣고, 게임 HUD/논리 월드/히트박스/입력좌표와 분리한다. 현재 시안은 메인 메뉴만 검증했으므로 모든 화면이 이미 동작한다고 말하지 않는다.
- [반응형·회전 시안](../validation/2026-11-02-v02-responsive-orientation/preview.html), Downloads/void-surfer-responsive-orientation-preview.html. 실제 소스 기반 단일 HTML, 원본5이미지, 이전 시안 보존.
- PC6크기의 주요8영역 역배율 좌표 동일/기준1600은 승인 DOM 일치/FHD렌더상한 유지. 모바일 가로5크기 전체 버튼44px·화면안, 세로2크기 안내·inert·키차단/PC세로는미차단/가로복귀해제. Space가이드새탭/375본문/JS0/원본7소스+5이미지SHA불변.
- 모바일 세로 안내는 우주 배경·원본 로고·청록 회전 아이콘·4.2초 잔잔한 모션(동작 줄이기 시 정지). 제목 '가로로 돌려주세요'. 이 외형 및 새 가로 메뉴 배치는 피드백 대기이며 실제 게임 타이머/회전 복귀 구현 완료가 아니다.

## A13 확정: 회전 중 감점 없는 중단 / 가로 후 계속하기

- 기존 일반 pause()는10점 차감하며 QTE 중 동작하지 않는다. 세로 회전 안내에 이를 그대로 연결하지 않는다.
- 사용자1번 선택: 세로 안내 중 게임·WASD 시간을 감점 없이 중단하고 플레이시간 기록에서도 제외한다. 가로 복귀 후 '계속하기'를 눌러 재개한다. 즉시 자동 재개는 채택하지 않는다.
- 직접 일시정지 -10점 규칙은 유지한다. 회전 전에 이미 수동 일시정지 상태였다면 이를 자동 해제하지 않는다.
- 메뉴·준비·사망 연출·결과창 등 실제 비행이 아닌 상태는 원래 화면을 복원하는 방향으로 설계한다. 회전 중 늦은 음악 준비 완료가 숨은 상태에서 출격을 시작하지 않게 별도 생명주기 검증이 필요하다.
