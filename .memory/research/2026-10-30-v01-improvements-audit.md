## 사용자 요청 원문 범위

1. 특수벽·투사체·레이저 이미지가 실게임에 적용됐는지 조사하고 수정 방향 결정.
2. 움직이는 벽을 일반벽과 구별되는 디자인으로 변경.
3. 화면 등장 시부터 움직임이 드러나도록 변경.
4. 플레이어 통과 무렵 구멍 이동을 멈춰 통과 중 끼임 사망 방지.
5. 보스마다 고유 패턴: 아이디어 제시 → 구현될 애니메이션 예시 → 승인 후 반영.
6. WASD 실패 페널티 강화 및 종류 추가 (강도/시간/종류는 아직 미정).
7. 키보드 ArrowUp을 클릭과 같은 상승 입력으로 추가. 반복/누르고 있기 처리 확인 필요.
8. 전체화면 렉의 원인 조사와 상세 비용/화질/효과 비교를 제시해 사용자가 조치를 선택.
9. 모바일 가로 플레이를 기준으로 UI/터치 조작 정비. 현재 터치 대시/발사/WASD 버튼은 존재.
10. 메인 화면 왼쪽 아래에 현재 버전 작게 표시. 현재 배포0.01-b, 다음 배포0.1, 이후0.11/0.12. 화면 버전/문서 버전 원본을 일치시킬 것.

## 성능: 확인된 구조 / 아직 확정하지 않은 원인

- 전체 버퍼 최대1920×1080. 배경0.5, 벽0.75, 투사체0.5, 레이저0.35 비율 레이어가 이미 존재한다. 기존 최적화를 새로 구현한 것처럼 설명하지 말 것.
- 레이저: 한 beam당 다중 blur ray와 움직이는 filament, gradient. 전역 공격은3구역에 이를 반복한다. 저해상도여도 그리기 호출/필터 비용이 남는 후보.
- 프레임마다 background/walls/projectiles/lasers 투명 버퍼 초기화와 전체 화면 확대 합성. 배경 반복 경계 다중drawImage도 후보.
- WASD 실패 효과 중 적 공격이 잘 보이도록 drawEnemy를 한 번 더 호출한다. 페널티 강화 시 중복 공격 그리기 부하도 측정할 것.
- HUD가 매 갱신마다 textContent/aria/SVG 속성을 갱신하며 일부 값은 매 프레임 같아도 쓴다. 실제 DOM 갱신 비용을 분리 측정할 것.
- 글리치 노이즈는240×135 캐시를22Hz로 갱신하며 메인 캔버스에는 확대해 그린다. 무조건 원인으로 단정하지 말 것.
- 이전 FHD 정책 검증은 Edge headless/disable-gpu 조건이다. FHD 일반/보스 p95 RAF33.3/50.0ms, draw+HUD6.0/7.1ms. 사용자 실제 GPU 환경의 원인 확정이나 FPS 보장은 아니다.
- 다음 성능 단계: 동일 장면/시드/프레임을 비교하며 레이어별 그리기, 필터/합성, HUD, 엔진 스냅샷을 계측. 조치별 프레임 비용 변화/화질 손실을 제시한 후 사용자 선택. 무단60FPS 제한/기체·보스 해상도 축소/효과 삭제 없음.

## D01 확정: 이동 구멍 정지 위치

- 사용자는 시간 기준을 재검토한 뒤 거리 기준1번을 선택했다. **플레이어 피격 박스 앞면과 벽 앞면 사이160논리px에서 구멍 이동이 완전히 멈춘다.** 화면 가로폭의 약17%이며 실제 CSS 픽셀 고정값이 아니다.
- 직전 접근 구간에서 부드럽게 감속한다. 구체적 감속 폭은 구현/예시에서 조정할 세부사항이며 아직 정확한 수치를 사용자에게 확정받았다고 주장하지 않는다.
- 정지 뒤 벽이 화면 밖으로 나갈 때까지 높이 유지. 벽의 가로 스크롤은 계속. 생성부터 움직임이 드러나야 하며 clamp/무작위 위상/첫 프레임 도약을 함께 해결한다.
- 이전0.4초 선택은 최종 규칙이 아니며 아래 계산은 재검토 근거로만 보관한다.

## 시간 기준을 폐기한 근거

사용자가 처음0.4초(2번)를 선택했지만 바로 시간 기준이 고속 VELOCITY에서 너무 일찍 멈추게 하지 않는지 재질문했다.0.4초를 최종 확정된 결정으로 취급하지 않는다.

- 기체 피격 박스 앞면x248, 처음 보이는 벽 앞면x960 기준 이동거리712. VELOCITY 일반 상한700이면 약1.017초 중 마지막0.4초 정지, 그전 움직임 약0.617초. 고속 보스 상한770이면 약0.925초 중0.525초 움직임. 생성x1032의 화면 밖 시간은 제외했다. 실제 속도는 보간/대시 간격 제한으로 낮을 수 있다.
-0.4초 정지 거리: 속도240/460/700/770에서96/184/280/308px. 시간은 반응 시간을 일정하게 하지만 보이는 정지 위치가 속도마다 달라진다.
- 비교 후 거리160px 선택 확정. 감속 폭40px는 당시 제안한 구현 후보이지 별도 확정 수치가 아니다. 거리 기준은 고속 반응 시간이 짧아지는 단점도 설명했다.
- 생성 즉시 움직임이 드러나게 하는 조건은 별개로 반드시 해결해야 한다. clamp 정지 구간/초기 위상/첫 프레임 도약 문제를 제거해 시간/거리 어떤 기준이어도 화면 진입부터 움직임을 읽을 수 있게 할 것.

모든 분기가 확정된 뒤 decisions에 Confirmed 문서 생성. 이후 memory-plan/execute 진행. 아직 코드 수정/보스 아이디어 확정/시안 승인/배포를 했다고 말하지 않는다.

## D02 확정: WASD 실패 페널티 범위

- 사용자1번 선택: 시야 방해만 강화하고 새로운 시각 효과 추가. 점수·조작/물리·레이저 충전에는 새 페널티를 주지 않는다.
- 사용자 글리치 요구: 순간적으로 화면이 아예 안 보일 정도로 강하게 치직이는 구간과, 다시 살짝 보이게 치직이는 구간을 번갈아 표현한다. 지속적으로 완전 차폐하는 효과로 해석하지 않는다.
- 이 단계에서는 보호 영역/빈도가 미정이었고, 이후 D04에서 리듬과 플레이어 주변 예외 제거가 확정됐다. 기존 렌더러의 적 공격 재그리기가 새 글리치를 덮어 지우지 않게 계획 단계에서 그리기 순서도 확인한다.
- 현재 지속시간8초. 지속시간 증가나 점수/충전 변경을 확정했다고 말하지 않는다. 실제 효과 예시를 보여주고 승인받은 뒤 반영한다.

## D03 초기 선택 → D05에서 시간 재검토

- 사용자1번 선택: 강한 차폐 한 번0.1초. 이후 다시 장면을 읽을 수 있는 약한 치직임으로 복귀.

## D04 확정: 리듬과 플레이어 주변 글리치

- 사용자 시안1번 승인: 약1.05~1.4초 간격의 강한0.1초 차폐 리듬 유지.
- 추가 지시: 플레이어 주변도 다른 화면 부분과 동일하게 글리치. 약한 구간의 기체 주변74×52 보호 영역도 제거한다. 강한 구간은 이미 전체를 거의 가렸고 계속 유지한다. 먹물의 보호 영역까지 제거하라고 지시한 것은 아니다.
- preview builder에서 복사한 함수의 글리치 보호 영역만 제거해 시안/Downloads 재생성. 실게임 challenge-effects.js는 아직 변경하지 않는다.
- 전체8초는 현재 게임 기준을 유지한 상태이며 별도 지속시간 변경 요청 없음. 새 효과의 종류/개수는 아직 미정.

## D05 추가2종 확정 / 글리치 시간은 슬라이더로 재검토

- 사용자2번 선택: 먹물·글리치에 새 시야 방해 효과2종 추가, 총4종. 구체적인 신규 효과는 아직 고르지 않았다.
- 사용자 요청으로 강한 차폐0.1초의 이전 확정은 재검토한다. 시안 슬라이더/숫자 입력에0.10~0.50초, step0.01을 제공하고 즉시 강한 구간의 길이에 반영한다. 기본 시작값0.10은 임시값이며 최종 선택이 아니다.
- 시작 간격/약한 효과/플레이어 주변 예외 제거/현재 총8초는 유지하고 한 번의 강한 차폐 시간만 비교한다. 현재 값으로 재생 버튼과 기존 정지 보기 유지.
- 실제 게임 설정은 바꾸지 않는다. 사용자가 시안을 조절해 최종 초값을 알려줄 때까지 시간을 다시 확정하지 않는다. 이후 신규 효과 후보의 이미지/애니메이션 선택을 이어간다.

## D06 확정: 최종 강한 차폐 시간0.18초

## D07 확정: 센서 균열 + 이온 안개 / 세부 형태·강도 조절 중

- 사용자1번 선택으로 신규 효과는 센서 균열과 이온 안개. 스캔 차폐는 선택하지 않았다. 따라서 먹물·글리치·균열·안개 총4종으로 구성한다.
- 사용자가 두 효과의 다양한 형태/강도를 보고 직접 슬라이더로 조절하기를 요청했다. `validation/2026-10-30-v01-glitch-preview/penalty-editor.html`과 Downloads 복사본을 제공한다.
