# Decisions: VOID SURFER

- Date: 2026-09-21
- Status: Confirmed

## D01. 플랫폼과 기술 스택
- **Chosen**: Vite + Vanilla JavaScript + Canvas 기반의 반응형 웹 게임
- **Rationale**: 16:9 Canvas 게임 루프와 Supabase SDK를 함께 관리하고 Vercel에 배포하기 적합하다.

## D02. 화면과 시각 스타일
- **Chosen**: 16:9 가로형 반응형 화면, 어두운 우주 배경과 네온 색상
- **Rationale**: 데스크톱·모바일 브라우저를 지원하면서 속도, WARNING, BOSS 상태를 명확히 표현한다.

## D03. 플레이어와 기본 조작
- **Chosen**: 네온 우주선을 플레이어로 사용한다. 중력으로 하강하며 클릭/터치할 때마다 상승 힘을 1회 적용한다.
- **Rationale**: 단순하고 즉각적인 아케이드 조작을 제공한다.

## D04. 경계와 충돌
- **Chosen**: 화면 위·아래 경계 또는 장애물에 닿으면 즉시 게임 오버
- **Rationale**: 플레이 영역과 실패 조건을 명확히 한다.

## D05. 일반 장애물
- **Chosen**: 우주 공간의 거대한 구조물이 화면을 가로막고, 세로 위치가 무작위인 하나의 통과 틈을 생성한다.
- **Rationale**: 좌우 진행과 틈 회피라는 핵심 플레이를 유지한다.

## D06. 특수 장애물
- **Chosen**: 특수 벽은 10점 이후부터 등장하며, 일반 구간 등장 확률은 20%다. 특수 벽의 정해진 판정 구간에서 SPACE를 누르면 약 0.6초 자동 대시로 통과한다. 일반 벽에서 SPACE는 아무 효과가 없다.
- **Rationale**: 초반 학습 구간을 보장하면서 특수 조작을 점진적으로 도입한다.

## D07. 특수 벽 타이밍 난이도
- **Chosen**: 평상시 SPACE 판정 허용 범위는 벽 기준 ±0.5초, WARNING 중에는 ±0.25초
- **Rationale**: 위험 구간에서 조작 정밀도를 높인다.

## D08. 이동 속도
- **Chosen**: 일반 속도는 20초마다 10%씩 단계적으로 증가한다.
- **Rationale**: 속도 변화를 플레이어가 인지하면서도 진행에 따라 자연스럽게 난도가 상승한다.

## D09. 점수
- **Chosen**: 장애물 하나를 통과할 때마다 1점. 일시정지할 때마다 10점 차감하며 최저 점수는 0점이다.
- **Rationale**: 점수 규칙을 단순하게 유지하고 일시정지 남용을 제한한다.

## D10. WARNING
- **Chosen**: 첫 WARNING은 20점에서 발동하고 이후 10점마다 발동한다. 해당 WARNING에서 생성된 특수 벽을 모두 통과할 때까지 유지한다. 일반 벽 틈은 기본 크기의 75%로 줄이고 특수 벽 확률은 50%로 높인다.
- **Rationale**: 점수 기반으로 위험 구간을 예측할 수 있게 하면서 평상시와 뚜렷한 난이도 차이를 만든다.

## D11. BOSS
- **Chosen**: 매 5번째 WARNING에서 BOSS가 발동한다. 화면 오른쪽에서 큰 적 캐릭터가 등장하며, 저속 50%·고속 180%·변속(50%↔180%) 중 하나를 무작위 선택한다. 해당 WARNING의 특수 벽을 모두 통과하면 종료한다.
- **Rationale**: 반복 플레이마다 다른 속도 압박을 제공하고, BOSS가 WARNING 흐름 안에서 명확한 이벤트가 되게 한다.

## D12. 경고 연출과 사운드
- **Chosen**: 중앙에 `WARNING` 또는 `BOSS WARNING` 배너를 표시하고 배경·장애물을 붉은 네온으로 전환한다. 효과음과 반복형 배경음악은 Web Audio API로 생성하며, 메인 메뉴와 게임 화면에 음소거 버튼을 둔다.
- **Rationale**: 외부 리소스 없이 상태 피드백과 오디오 접근성 제어를 제공한다.

## D13. 게임 흐름과 튜토리얼
- **Chosen**: 매 게임 시작 전에 한국어 조작법 안내 화면을 표시하고 `게임 시작` 버튼으로 진입한다. 게임 오버 후 `바로 재시작`을 누를 때만 안내를 생략하며, 메인 메뉴로 돌아간 뒤 다시 시작하면 안내를 표시한다.
- **Rationale**: 첫 진입뿐 아니라 규칙을 잊은 사용자를 돕되 즉시 재도전 흐름은 빠르게 유지한다.

## D14. 일시정지
- **Chosen**: 화면 일시정지 버튼과 `P`/`Esc` 키를 지원한다. 일시정지할 때마다 점수 10점을 차감하고 0점 아래로 내려가지 않는다.
- **Rationale**: 데스크톱·모바일 모두 중단할 수 있지만 반복 일시정지에는 비용을 부여한다.

## D15. 모바일 조작
- **Chosen**: 터치는 클릭과 같은 상승 입력으로 사용하고, 화면의 가상 `SPACE` 버튼은 특수 벽 대시에 사용한다.
- **Rationale**: 반응형 웹 화면에서도 핵심 조작을 유지한다.

## D16. 인증과 계정
- **Chosen**: 게임 시작 전 Microsoft 계정 로그인을 필수로 한다. Supabase Auth의 Microsoft OAuth를 팝업 방식으로 사용하며, 로그인 실패·취소 또는 서버 연결 실패 시 게임을 시작하지 않고 오류를 표시한다. 메인 메뉴에 로그아웃 버튼을 제공한다.
- **Rationale**: 모든 점수에 계정을 연결하고 계정 전환도 지원한다.

## D17. 리더보드 저장
- **Chosen**: Supabase PostgreSQL에 사용자별 최고 점수만 저장하고, 더 높은 점수일 때 갱신한다. Microsoft 표시 이름을 로그인할 때마다 최신 값으로 갱신한다. 인증 사용자만 점수를 제출할 수 있도록 기본 서버 검증과 RLS/RPC를 적용한다.
- **Rationale**: 리더보드의 중복을 줄이고 최소한의 서버 권한 검증을 확보한다.

## D18. 리더보드 범위와 동점 처리
- **Chosen**: 전체 누적 최고 점수 리더보드를 사용한다. 동점이면 먼저 달성한 기록을 높은 순위로 처리한다. 게임 오버 직후 상위 10명과 플레이어 주변 순위를 함께 표시한다.
- **Rationale**: 장기 경쟁과 현재 위치 확인을 동시에 제공한다.

## D19. 게임 오버와 리더보드 오류
- **Chosen**: 게임 오버 직후 점수·리더보드·내 순위를 표시하고 `바로 재시작`과 `메인 메뉴` 버튼을 제공한다. 리더보드 조회 실패 시 점수와 두 버튼은 즉시 표시하고, 리더보드 영역에 실패 안내와 `다시 시도` 버튼을 표시한다.
- **Rationale**: 네트워크 문제로 재도전 흐름이 막히지 않게 한다.

## D20. 배포와 연동 안내
- **Chosen**: Vercel에 배포한다. Supabase 프로젝트와 Microsoft OAuth 설정은 아직 없으므로 구현에 환경 변수 예시, SQL 스키마/RLS/RPC, Microsoft Entra 앱 등록, Supabase Provider 설정, Vercel Redirect URL 및 환경 변수 설정 문서를 포함한다.
- **Rationale**: 사용자가 인증·리더보드 인프라를 직접 구성할 수 있도록 전체 절차를 제공한다.
