- Date:2026-10-29
- Status: Confirmed from the user's four requested changes and current code. No unresolved design branches.

## D01 Boss-only encounters
- Replace each standalone WARNING opportunity with a real BOSS encounter: normal → boss → normal → boss. First threshold remains20; after each clear choose5–8 points beyond the clear score. Keep boss entry draining/blackout/siren, HP, +10 clear reward, portal and patterns unchanged.
- Boss number and cleared-boss count must count actual bosses, not half the former WARNING index. First-clear unlocks after boss1; ambient lasers unlock after boss2. Boss walls never grant pass points, including leftover walls after clear.
- Keep archived WARNING rules and source reference for a future redesigned return. Dormant names/constants may remain for compatibility, but no standalone WARNING session is reachable in ordinary runs. No new revival design is invented.
- New explicit fixture option `initialClearedBossCount` uses actual boss counts; retain `initialCompletedWarningCount` as a legacy test/review alias converted by floor(count/2).

## D02 Menu sound
- Current controller calls audio unlock only at beginPlaying. Unlock in the first eligible pointer/keyboard gesture on the app before a run, with deduplication, rejection retry and listener cleanup. Preserve mute/pause and no forced autoplay bypass.
- Browsers may block audible sound before first interaction; show no new obstructive start dialog. First menu interaction must be enough, without visiting gameplay. Touch unlock uses a completed pointer gesture.
- When opening menu music, load the menu track only; don't prefetch unrelated first-stage normal/boss audio. Keep stage preload for actual gameplay and normalize scene IDs before comparing.

## D03 Menu motion
- Existing menu paint reconstructs the hero DOM and restarts CSS animation on account/mute/status repaint. Preserve the connected preview when selected aircraft is unchanged, and avoid redrawing an unchanged menu canvas on these repaints.
- Group image and exhaust in one transform-only compositor motion wrapper; keep expensive sprite glow static. Preserve chosen art, dimensions, color and reduced-motion behavior.
- Record matched before/after menu frame observations. Initial baseline:1440px software headless,180 intervals, median/p95≈16.7ms, no >33ms frames, first menu click created no AudioContext. This does not reproduce every user's GPU lag; don't claim universal FPS gains.
