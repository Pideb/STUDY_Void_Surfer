- Status: Confirmed

- [기존 게임·시각 결정](./2026-11-02-v01-gameplay-visual-polish.md)의 규칙은 아래 명시한 변경 외 그대로 포함한다. 기존 v0.1 계획은 이 계획으로 대체한다.

## D01. 버전과 과거 표시
- **Chosen (사용자)**: 과거 두 버전의 사람에게 보이는 이름은 v0.1 / v0.1b, 이번 다음 실제 배포는 v0.2.
- **Rationale**: 과거 표시와 새 배포 이름이 중복되지 않게 한다.
- 현재 실제 운영 내부 id0.01-b와 배포 증거는 유지한다. 과거0.01v/0.01-b 내부 식별자·보호 HTML·SHA·Git/Actions 기록은 변경하지 않는다. 새 HTML 출력은 displayVersion으로 표시하고 필요 시 원본 기반 별도 표시용 사본을 제공한다.
- versionBase0.2/nextVersion0.2로 설정할 권한은 이번 사용자 명시 변경에 근거한다. 실제 currentVersion 승격은 배포 요청 때 release:prepare로만 한다. 이후 기존 문자열 순번 알고리즘을 사용하며 새 기준0.3/1.0으로 자동 승격하지 않는다.
- 단순 문서/계획 갱신은 새 배포가 아니다. 공식 문서 동기화 gate와 운영 검증 증거 절차는 보존한다.

## D02. 피드백용 전 기체 임시 해금
- **Chosen (사용자)**: v0.3 전까지 로그인·게스트 모두 NOVA/AEGIS/VELOCITY 사용 가능. 기체 선택에 정확히 '다음 버전까지 임시 해금' 문구를 표시한다.
- **Rationale**: 최고기록과 무관하게 피드백을 수집한다.
- 최고기록/기체 성능/점수 배율을 조작하지 않는다. 공통 선택 정책을 사용하며 UI·늦은 기록 응답·엔진 start 검증·게스트 default 강제 경로 모두 같은 정책을 따른다.
- 임시 해금은 별도 정책 플래그/종료 milestone0.3로 관리한다. 기존 문자열 배포 순번을 실수 비교(0.21>0.3 등)하지 않는다. 기준0.3 배포를 준비하면 자동 검증으로 종료를 강제하고 원래 계정 AEGIS50/VELOCITY100·게스트NOVA 정책으로 복구한다.
- 게스트 점수/랭킹 저장 금지는 유지한다. 비공개 사용 통계는 D07의 별도 기록이다.

## D03. 메뉴 키보드 탐색
- **Chosen (사용자)**: 메인·기체 선택·안내·일시정지·랭킹·관리자 대화상자 등 메뉴를 방향키로 이동, Space로 선택. 선택 강조는 기존 hover 효과와 동일.
- **Rationale**: 마우스 없이도 조작한다.
- 배치에 맞는 상하좌우 탐색/비활성 항목 건너뛰기/새 메뉴의 초기 초점/대화상자 내부 초점 보존을 구현한다. 기존 Tab/Enter 접근성은 유지한다.
- 게임 플레이/WASD 입력·입력창·브라우저 기본 단축키와 분리한다. held/repeat/keyup 후 합성 click 중복 방지. 동적 렌더/로딩으로 선택이 사라지면 유효한 항목으로 복구한다.
- 게임오버는 다음 예외다.

## D04. 게임오버 입력과 화면
- **Chosen (사용자)**: '재시작' 버튼 삭제. ESC는 메인 메뉴, 그 외 새 키는 재시작(방향키/Space/Enter 포함). 파일럿 랭킹은 포인터로만 선택.
- 팝업 밖 클릭/모바일 터치는 재시작. 팝업 내부 일반 클릭은 재시작하지 않으며 메뉴/랭킹 버튼 포인터 동작은 유지한다.
- 팝업 바깥을 살짝 어둡게 하고 화면 하단에 '아무 키 입력/화면 클릭을 통해 재시작'을 선명한 네온 스타일로 표시한다. ESC 예외는 키 규칙에 그대로 적용.
- **Rationale**: 빠른 재도전과 읽기 쉬운 결과창.
- 사망 전부터 누른 키/반복/이벤트 전파로 즉시 결과창이 닫히거나 두 번 재시작하지 않게 한다. 최상위 회전/복귀 안내가 있을 때 게임오버 단축키는 실행하지 않는다.
- 결과창을 즉시 떠나도 기존 run의 점수 저장/통계 저장은 완료 또는 재시도되어야 한다. 늦은 응답은 새 run 화면/기체를 덮어쓰지 않는다. 관리자·게스트 랭킹 제외 정책 유지.

## D05. 플레이어용 HTML / 가이드 링크
- **Chosen (사용자)**: 조작법과 개발자가 수동 작성하는 업데이트 내역을 담는 플레이어용 HTML을 새로 만든다. 메인 메뉴에서 새 탭으로 연다.
- 가이드 왼쪽 / 음량 오른쪽의 같은 보조 행 배치를 승인했다. 큰 버튼 행 추가 없음. 기존 청록 hover/방향키 선택 강조를 사용.
- **Rationale**: 게임 화면을 유지하며 사용자가 안내를 읽는다.
- 개발자 수동 원고를 별도 원본으로 보존하고 자동 docs 생성/배포가 문구를 임의 작성·덮어쓰지 않는다. 초기 업데이트 원고가 없으면 빈 상태를 표시하며 가짜 변경 내역을 채우지 않는다.
- 최종 정적 안내는 public/guide/index.html로 배포 가능하게 만들고 코드 예제·관리 통계·개발 시안은 넣지 않는다.
- [링크 배치 승인](../validation/2026-11-02-v02-menu-guide-v2/preview.html). 시안의 Blob 페이지는 동작 확인용으로 최종 문서가 아니다.

## D06. 개발 예시 보관
- **Chosen (사용자)**: 관리 레퍼런스 HTML에 기존 개발 예시 링크 탭 추가. 로컬 개발 자료로만 보관, 게임 배포에 포함하지 않는다.
- **Rationale**: 승인/폐기 시안과 조절 도구를 잃지 않는다.
- 독립 preview/review/playtest 목록을 명시적으로 관리하고 날짜·용도·상태·실행 조건을 기록한다. content 조각/디버그/측정 fixture 전체를 무차별 공개하지 않는다.
- 원본 상대 링크와 필요한 JS/이미지 의존성을 검증한다. Downloads 사본은 프로젝트 루트를 알 수 없을 때 경로를 정직하게 안내하고 로컬 링크가 원격에서도 열리는 것처럼 표시하지 않는다.
- .memory 전체를 public/dist에 복사하지 않는다. 관리 HTML과 플레이어 HTML은 별도 대상이다.

## D07. 개발자용 비공개 플레이 기록
- **Chosen (사용자)**: 로그인·게스트 모두 Supabase 기록, 개발자만 조회. 사용자/공개랭킹/관리자 테스트 게임 UI에 시간·총횟수 조회 제공 없음.
- **Rationale**: 피드백용 사용 통계를 실제 플레이 단위로 확인한다.
- 로그인은 auth.uid, 게스트는 익명 식별자로 구분한다. 게스트 식별자는 점수가 아닌 통계용이며 저장소 삭제/다른 기기에서 별개가 될 수 있다. 계정과 자동 병합하지 않는다.
- 실제 플레이 시작하면 총횟수1회. 출격 준비·준비취소는0회. 중도 이탈 포함, 사망 완료와 미완료/이탈 상태 별도.
- 시간은 실제 시작~사망 판정. 출격 준비·일시정지·회전 중단 제외, WASD 챌린지 포함. 사망 폭발/결과창 시간 제외. 물리 dt상한이나 게임 elapsedSeconds를 그대로 사용하지 않는다.
- 동일 run의 시작/끝/재시도는 중복 집계하지 않는다. 단순 누적 counter를 덮어쓰는 대신 run 테이블에서 집계한다.
- 탭 강제 종료/네트워크 단절 시 정확한 종료 시각은 보장하지 않는다. 시작 레코드를 남기고 미완료로 구분, 사망 기록을 만들어내지 않는다.
- 별도 테이블의 SELECT를 anon/authenticated에 열지 않는다. 기존 leaderboard RLS/read RPC를 재사용하지 않는다. 브라우저에 서비스/관리자 비밀키를 넣지 않는다.
- 쓰기 전용 RPC의 run별 난수 증표는 해당 run 쓰기에만 쓰며 서버 관리자 권한이 아니다. 클라이언트 시간은 서버 검증하되 공인된 부정행위 방지 기록이라고 주장하지 않는다.
- 기존 점수 저장/게스트 기록 금지와 독립, 실패 시 게임을 막지 않고 제한된 재전송 큐로 처리한다. 관리자의 테스트 run은 테스트 표시로 분리해 조회할 수 있다.

## D08. 처음 세 보스 속도 패턴
- **Chosen (사용자)**: 첫 보스 저속 → 두 번째 고속 → 세 번째 변속 → 네 번째부터 기존 독립 균등 무작위.
- **Rationale**: 처음에는 유형을 순서대로 익히고 이후 무작위성을 유지한다.
- 새 run/즉시 재시작은 저속부터. 지역/외형 순서 랜덤은 유지. 셔플 백/연속 금지 등 새 제약은 추가하지 않는다.
- 기존 속도 배율/변속 주기/2초 보간/VELOCITY 보정/벽 모두 지나간 후 진입 조건 유지. 예고~클리어 동안 선택한 패턴을 다시 뽑지 않는다.
- 기존 difficulty.js와 game-engine.js::startWarningIfNeeded/beginWarningSession 양쪽에 일관되게 적용한다.

## D09. PC 메뉴 비율
- **Chosen (사용자)**: 화면 대비 같은 비율, PC 시안 승인.
- **Rationale**: FHD·4K에서 글자만 작게 남지 않도록 메뉴 전체를 일괄 확대/축소한다.
- 구현 기준은 승인된1600×900 메뉴. scale=min(width/1600,height/900), 울트라와이드는 여유를 둔다. 기준값은 사용자 별도 수치 선택이 아니라 승인 시안을 보존하기 위한 구현 기준.
- 메뉴/팝업 전체에 적용하고 게임 HUD/논리 월드/충돌/입력좌표/캔버스 FHD상한과 분리한다.
- [PC 승인 시안](../validation/2026-11-02-v02-responsive-orientation/preview.html). 메인 메뉴만 시안 검증했으므로 나머지 메뉴는 구현 때 검증한다.

## D10. 모바일 가로 확대 메뉴
- **Chosen (사용자)**: [확대안](../validation/2026-11-02-v02-mobile-menu-large/preview.html)1번 최종 승인.
- 왼쪽 브랜드/기체/계정, 오른쪽 큰 메뉴. 주요20px/60px, 높이360 이하19px/56px. 가이드·계정16px, 보조52~56px. 가이드 왼쪽/음량 오른쪽.
- **Rationale**: PC UI를 작게 축소하지 않고 실제 터치와 가독성 확보.
- safe-area/짧은 화면/동적 브라우저 높이를 고려한다. 기존 게임 중 대시·발사64CSSpx 및 WASD56px/gap12 규칙은 보존한다.
- 기존 게임 특수벽 초록 가이드 등 게임플레이 시각과 메뉴 확대를 혼동하지 않는다.

## D11. 모바일 회전 안내와 복귀
- **Chosen (사용자)**: 가로 모드 필수. 세로에서는 승인된 우주+청록 네온 회전 안내, '가로로 돌려주세요'. PC 세로 창은 차단하지 않는다.
- 세로 전환 시 게임·WASD·관련 진행 시간을 감점 없이 중단한다. 플레이시간 기록에서도 제외한다.
- **가로 복귀 후 '계속하기'를 눌러 재개**(마지막 사용자1번). 자동 재개안 미채택. 이미 수동 일시정지 상태였다면 그 상태를 유지한다. 직접 pause의 -10점은 그대로.
- **Rationale**: 기기를 다시 잡기 전에 떨어지거나 QTE가 끝나는 것을 방지한다.
- 메뉴/결과 등 비행이 아닌 화면은 원래 화면을 복원한다. 준비 중에는 늦은 음악 완료/10초 fallback이 숨은 상태에서 비행을 시작하지 않게 한다. 안내 중 뒷면 입력/keyup 합성 클릭이 통과하지 않게 한다.
- OS 회전 강제 보장을 뜻하지 않는다. 실제 viewport 방향과 모바일 판정에 따라 차단·해제한다. 동작 줄이기 설정에서는 회전 아이콘 애니메이션 정지.

## D12. 기존 확정 규칙과 제외 범위
- 기존 이동벽160px 정지/보스 차수 난이도/특수 .30초/WASD4초·2.5초/오타 지속·.15복귀/4종8초페널티/.18글리치/실제발사탄속/6고유패턴/승인v3재질/품질유지최적화는 앞 결정 문서대로 포함한다.
- 독립 WARNING 복구/일반 속도·중력·기체 점수 변경/투사체 반사 HP 클리어/후반HP5/새결제·서버 이전 요청 없음.
- 새 버전 배포 요청 전 prepare/push/원격 배포를 하지 않는다. 원격 스키마 적용과 실제 권한 검증은 실행에서 접근 가능한 수단으로 확인하고 미실행이면 배포 전 필수 작업으로 남긴다. Docker 직접 실행은 이전 사용자 환경 제약에 따라 요구하지 않는다.

## D13. 보스 간격: 첫20벽 / 새 스테이지 도착 후15벽
- **Chosen (사용자)**: 첫20벽 통과, 이후는 다음 스테이지 도착 후 일반 구간15벽 통과마다 보스. 보스전 벽과 클리어 후 전환 대기 벽은 제외한다. 마지막 답변1번으로 기준점 확정.
- **Rationale**: 점수 보상·감점·기체 배율과 관계없는 일정한 템포.
- 일반/특수/이동/혼합 모두 벽 오브젝트 하나 통과=1회,같은id중복없음. 새run은첫20으로초기화하고다음스테이지전환완료시15로새로시작한다.
- 기존 첫20점/도착후+15~20점 트리거를 활성 런타임에서 대체한다. 점수·속도 증가·해금 등 다른 점수 규칙은 변경하지 않는다.
- 목표 벽 수만큼만 정상 구간 생성 슬롯을 발급해20번째/15번째 통과 시 이미 다음 벽이 줄지어 생성된 상태가 되지 않게 한다. 마지막 기존 벽이 화면 끝까지 나간 후 보스 진입·속도 변화하는 기존 drain 규칙 유지.
- 첫저속/둘고속/셋변속/4이후랜덤과 지역·외형순서 정책은 그대로다.

## D14. 동점 랭킹: 해당 최고점수 run의 긴 플레이시간 우선
- **Chosen (사용자)**: 점수가 같으면 사망할 때까지 플레이시간이 긴 사람이 높은 순위. 랭킹 화면에서는 시간 확인 불가.
- **Rationale**: 동일 점수의 생존 기록을 보조 기준으로 사용한다.
- 정렬은 best_score DESC → 해당 record의 duration_ms DESC → achieved_at ASC → user_id ASC. 시간 정의는D07/D11 그대로(QTE포함/준비·pause·회전제외/사망판정종료).
- 동일 계정이 같은 최고점수로 더 오래 생존한 경우도 최고기록 부가값·기체·달성시각을 그 run으로 함께 갱신한다. 낮은 점수의 긴 시간을 최고점수에 붙이지 않는다. 점수와 시간까지 같으면 기존 기록 유지.
- 기존 기록의 미측정 시간은0/unknown으로 처리,추정·다른run backfill금지. 구형2·3인자 제출RPC도0/unknown으로 호환하며 이미 저장된 같은 점수의 긴 시간을 지우지 않는다.
- 시간은 서버의 별도 read 차단된 부가테이블에 둔다. 현재 사용자 SELECT가능한player_scores에 시간 컬럼을 추가하지 않는다. submit_score 반환·랭킹RPC·사용자타입/DOM/data속성/툴팁에 시간 원본을 넣지 않는다.
- 공개 전체/로그인top/자기주변/고정자기순위의 서버정렬은 동일하다. 게스트·관리자run은 기존처럼랭킹제외. private 통계쓰기의 성공을 기다리느라 최고점수 저장이 멈추지 않게 같은 frozen 종료시간을 제출한다.
- 기존SQL을 소급수정하지않고새migration으로작성한다. 실제원격적용·역할별읽기거절은배포전gate로검증한다.
