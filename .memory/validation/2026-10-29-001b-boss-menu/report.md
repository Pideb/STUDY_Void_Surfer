## T04 후속 수정 — 최신 규칙/검증

- 사용자의 추가 확정에 따라 **보스 재등장은 WARNING5~8점과 분리**했습니다. 첫 보스20점은 유지하고, 다음 보스는 **다음 스테이지 포털 전환 완료 시점 점수 + 무작위15~20점**입니다. 아래 초기 T01–T03 기록의5~8점은 T04로 대체된 중간 이력입니다.
- 클리어 보너스10점은 도착 전 지급하며 새15~20점 간격에 포함하지 않습니다. 포털 중 감점은 도착 점수에 반영합니다. 도착 후에는 절대 점수 기준을 유지하고 감점 시 재추첨하지 않습니다. 재시작하면 첫20점으로 초기화합니다.
- 전환 중에는 지난 보스 기준 점수를 넘겼더라도 다음 보스 판정/배율을 적용하지 않습니다. 보관 WARNING의 chooser/상수5~8은 변경하지 않았습니다.
- 수정: `constants.js`의 `BOSS_REENTRY_SCORE_MIN/MAX=15/20`, `difficulty.js`의 `chooseBossReentryScoreStep()`, `game-engine.js`의 포털 완료 시 예약. 핵심은 `nextWarningScore = getScore() + chooseBossReentryScoreStep(rng)`를 클리어가 아닌 포털 완료에서 실행하는 것입니다.
- 관련5개 파일92개 검사, 전체 **57개 파일718개 검사 통과** (`t04-full-tests.log`). 빌드100 modules/JS400.79kB/CSS19.69kB, 설정 검사도 통과했습니다.
- 실제 엔진 통합 검사에서 RNG0→15, RNG1→20 두 경우를 보스1~2 클리어까지 비행했습니다. 포털 중 감점·숨겨진 stage-swap 시점·완료 후 기준 고정·점수 보상·보스 벽 무점수·재시작을 함께 확인했습니다. 별도 단위 검사는 중간값.5→18도 확인합니다.
- HTML/README/버전 목록/Downloads를 새 규칙으로 갱신했습니다. 표기는 `3928989 + T04`, 정확한3개 런타임 파일 지문은 `versions.json`의 `runtimeFingerprint`입니다. 과거 캡처와 소리 실측은 이전 T01–T03 증거이며 이번 간격 검증으로 새로 측정했다고 주장하지 않습니다.
- 갱신한 HTML은1440/768/375px·필터/검색·탭·인쇄·오프라인·복사 기능 재검사를 통과했습니다. 새 간격 문구와T04 복사 문자열도 확인했고 누락 이미지·브라우저 예외는 없습니다. 새 HTML SHA와 과거0.01v 무결성/Downloads 동일성은 `html-build.json`/`asset-audit.json`에 기록했습니다. 인접 문제 추가 발견 없음. 로컬 작업이며 **아직 배포하지 않았습니다**.

## 반영한 요청

1. 독립 WARNING을 보스로 교체했습니다. 일반 → 보스 → 일반 → 보스이며 첫 기준 20점, 이후 클리어 점수에서 5~8점 뒤입니다. 보스 번호·해금은 실제 클리어 횟수로 계산합니다. 보스가 만든 벽은 클리어 후 뒤에 남아도 점수를 주지 않습니다. 보스 HP·기체 밸런스·기존 진입/포털 연출은 유지했습니다.
2. WARNING을 잊지 않도록 [당시 설계·원본·복원 주의점](../../archive/2026-10-29-warning-0.01v.md)을 보관했습니다. 기존 이름과 일부 휴면 코드는 호환성을 위해 남아 있지만 일반 실행에서 독립 WARNING은 시작하지 않습니다. 부활 방식은 아직 정하지 않았습니다.
3. 첫 메뉴 클릭·터치 완료·일반 키 입력에서 오디오를 활성화합니다. 중복 요청, 거절 후 재시도, 종료 시 리스너 정리를 포함합니다. 메뉴곡만 먼저 불러오고 실제 플레이에 들어갈 때 지역곡을 준비합니다. 첫 사용자 동작 전 무음은 브라우저 정책에 따른 제한입니다.
4. 같은 기체의 메뉴 갱신 시 연결된 DOM·애니메이션 시간을 유지합니다. 기체/배기를 하나의 transform-only 3D 모션 래퍼로 묶고 정적 광원과 분리했습니다. 음소거·계정 정보 갱신에서 부유 모션이 처음으로 되돌아가지 않으며, 동작 줄이기 설정도 지킵니다.

## 운영 상태와 남은 한계

기존 Azure 운영 로그인은 앞서 사용자가 이름 표시까지 확인했습니다. 이번 작업에서 실제 계정으로 운영 점수 제출을 새로 실행하지 않았습니다. 운영 DB·인증·배포 설정을 바꾸지 않았고 **0.01-b를 공개 링크에 배포하지 않았습니다**.

브라우저는 최초 사용자 동작 전에 소리를 제한할 수 있습니다. 자동재생 제한을 우회하지 않고 첫 메뉴 동작으로 충분하도록 수정했습니다. 참고: [MDN Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices#autoplay_policy).
