# T01 FHD 측정

실제 엔진·자산·렌더러·HUD를 같은 시드/초기 상태/고정된 검증용 게임 시간 단계(16.667ms)로90프레임씩 그렸습니다.20프레임 준비 뒤 실제 RAF 전달 간격과 draw+HUD 시간을 수집했습니다. 이 고정 시간 단계는 비교용 fixture에만 있으며 실제 게임의 시간 계산/RAF는 변경하지 않았습니다.

기존 해상도 정책은 `c29380b`의 코드를 `resolution-baseline.mjs`로 고정했습니다. `renderer-baseline.mjs`는 실제 렌더러의 해상도 import만 그 정책으로 연결합니다. 같은 페이지/브라우저에서 최종 정책과 비교했습니다. Edge 헤드리스 `--disable-gpu`,DPR1 조건이며 물리 GPU FPS가 아닙니다.

| 화면/장면 | 버퍼 전→후 | 프레임 p95 전→후(ms) | 그리기+HUD p95 전→후(ms) |
| --- | --- | --- | --- |
| FHD 일반 |1920×1080→동일|33.2→33.3|6.5→6.0|
| FHD 보스 |1920×1080→동일|50.0→50.0|7.0→7.1|
|4K 일반|3840×2160→1920×1080|83.4→33.4|21.8→6.7|
|4K 보스|3840×2160→1920×1080|133.4→50.0|122.2→7.0|

4K 조건의 그리기 부담 감소를 관찰했습니다. FHD 자체는 동일 정책이라 개선을 주장하지 않습니다. 사용자 PC의 하드웨어 가속/고주사율 환경을 재현한 것은 아니므로 보편적인 FPS나 완전한 프레임 드롭 해소를 보장하지 않습니다. 검증용 중력0/충돌우회, 점수10또는20을 사용했습니다.

- 원자료: `baseline-render.json`, `final-render.json`, 같은 접두어의 화면 캡처.
- 관련4개 파일67개 테스트 통과: 해상도 상한/초광폭/세로/DPR/resize/reused layers/논리좌표·피격 판정.
- 변경 코드: `min(DPR,1920/width,1080/height)`로 버퍼 크기만 제한. 기존 레이어 비율·논리 세계·물리·RAF 유지.
- 추가 범위 밖 변경: 없음. 배경 반복/발광/HUD의 별도 재설계는 하지 않았습니다.
