## 실제 브라우저 증거

`startup.html/mjs`는 실제 엔진/오디오/컨트롤러/렌더러/자산을 사용합니다. 음악 네트워크에 의도적인 지연/실패를 넣었고, 반복 검증을 위해 중력0과 게스트 auth stub을 사용했습니다. 원격 계정/DB 쓰기는 없습니다.

- ready: 준비 중 스냅샷이 고정됐고 정상 게임/BGM 진입을 약1.27초 시점에 관찰했습니다. 재시작은 캐시를 사용하며 추가 요청 없이 같은 gate를 통과했습니다.
- timeout: 게임곡을11.2초 지연시켜 약10.06초에 무음 출격, 이후 같은 스테이지 곡만 재생했습니다.
- failure: 실패 응답에서 약10.07초에 무음 출격했고 합성 BGM·무한 재시도가 없었습니다.
- late-menu: 메뉴곡 응답이 뒤늦게 도착해도 게임곡을 덮어쓰거나 메뉴 음악을 재개하지 않았습니다.
- cancel: 로딩 중 메뉴로 복귀하면 뒤늦은 완료가 게임/게임곡을 시작하지 않았습니다.
- 기본 메뉴곡은 출격 시 현재 오디오 시각에 즉시 중단되며 이전+.24초 잔여음이 없습니다. 게임곡 시작 시 실제 엔진 상태는playing이었습니다. 코드 예외0. 원자료 `startup-verification.json`.

처음에는 기존 Vite4186 서버가 새 `prepareTrack` 없이 옛 음악 모듈을 제공해 예비 검증이 실패했습니다. HTTP 응답이 디스크 소스와 다른 것을 확인하고 사용자 서버는 건드리지 않은 채 별도4187 서버를 시작했습니다. 새 서버에서 위 시나리오가 통과했습니다. 이 실패를 소스 수정 성공으로 숨기지 않으며 운영 번들은 별도로 해시 일치를 확인했습니다.
